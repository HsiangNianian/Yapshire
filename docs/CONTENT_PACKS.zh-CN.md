# 内容包规范 v2

[English](CONTENT_PACKS.md)

**尚未发布的源码版本：**内容包格式 **2**、世界格式 **3**、联机协议 **5**。
客户端和服务端需要匹配。已发布的 v0.7.1–v0.7.2 使用协议 3、内容包格式 1，
无法加入本开发版本的房间。新版加载器仍能读取格式 1 内容包和旧地图。

官方资源从 `assets/packs/yapshire/pack.json` 加载，社区内容使用相同的加载器、校验和文件格式。
一个世界使用一个完整内容包。本版包含有限地图、图集、物件和已有玩法的交互定义；
依赖解析、脚本 Mod、自动下载美术资源、无限地图和挖掘建造系统留待后续。

## 做出自己的内容包

1. 把程序旁的 `assets/packs/yapshire` 复制为 `assets/packs/my_pack`。
2. 修改副本 `pack.json` 的 `id` 为 `my_pack`，填写自己的 `version`，删除 `legacy_tiles`。
   原有资源 ID 可以保留；新增资源使用自己的命名空间，例如 `my_pack:brick/wall`。
3. 用 [Tiled](https://www.mapeditor.org/) 打开 `maps/town.tmj`。使用有限正交地图、16×16 网格、未压缩 JSON 数组。
4. 执行 `yapshire-server --maps assets/packs/my_pack --check` 校验。
5. Linux/macOS：`YAPSHIRE_PACK=my_pack ./yapshire`。
   PowerShell：`$env:YAPSHIRE_PACK='my_pack'; .\yapshire.exe`。
6. 把完整目录分享给朋友。大家安装并选择同一内容包后，加入房间时自动同步服务端的地图布局。

游戏内编辑器通过“下一张地图”浏览清单中的地图，图层支持翻页，调色板读取全部图集。
画笔和填充会自动连接地形；“物件印章 / P”在点击的网格位置放下模型的**锚点**。
可直接选择对象层，也可选择 tile layer，编辑器会创建或使用同深度的配套对象层。
选中对象层后，可擦除或吸取整个物件，撤销、重做和保存均保留其身份与状态。
旧版 prefab 印章仍按左上角绘制图块。出生点、矩形交互和背景层会保留并预览，请在 Tiled 中编辑。
金色辅助标记显示地图对象的位置。

官方本地覆盖文件仍保存在 Yapshire 数据目录的 `maps/` 中；其他内容包使用 `packs/<包名>/`。
`YAPSHIRE_MAP_DIR` 可覆盖保存目录。保存时会补齐缺失的清单、图集和图片，并按清单路径存放地图，
例如保存目录下的 `maps/town.tmj`。已经存在且内容不同的美术文件不会被覆盖。
尚未生成的其他地图会用上次保存的布局补齐，使目录成为完整内容包；其他地图的未保存草稿仍留在编辑器中。
更新内容包前先关闭游戏，保留自己的地图草稿，并同步更新配套资源。

## 目录与稳定 ID

```text
my_pack/
  pack.json
  blocks/oak.json
  models/oak.json
  textures/oak/trunk.png + leaves.png
  terrain/ground.tsj + ground.png
  terrain/water.tsj  + water.png
  buildings/tackle.tsj + tackle.png
  objects/harbor.tsj + harbor.png
  backgrounds/street.png
  maps/town.tmj
  maps/tackle-shop.tmj
```

可直接参考[官方清单](../assets/packs/yapshire/pack.json)：

| 字段 | 用途 |
| --- | --- |
| `format` / `id` / `version` / `tile_size` | 格式版本 `2`、包名、内容版本、网格 `16` |
| `blocks` | 稳定 ID 到物件定义 JSON 路径的登记表 |
| `models` | 稳定 ID 到模型 JSON 路径的登记表 |
| `tilesets` | 按顺序登记的外部 `.tsj` 路径 |
| `images` | 允许背景图层引用的 PNG 路径 |
| `maps` | 每张地图的稳定 `id`、相对 `path`、显示 `title` 和 `indoors` |
| `entry` | 初始地图 `map` 及出生点名称 `spawn` |
| `prefabs` | 可重复使用的完整物件图块排列 |
| `terrains` | 按连接掩码排列的 16 个地形变体 |

清单中的路径相对内容包根目录，Tiled 引用相对当前地图或图集，例如 `../terrain/ground.tsj`。
禁止绝对路径、反斜杠、盘符以及指向包外的符号链接。
ID 使用 `namespace:name`，区分大小写且不能重复。命名空间使用小写 ASCII 字母、数字和 `_`，
名称额外允许 `-` 和 `/`。

每个 `.tsj` 图块必须带字符串属性 `id`。图集中的数字 `id` 与地图里的 `firstgid` 只是 Tiled 地址，
不承担资源身份。地图保存字符串属性 `yapshire:palette`，记录上次保存时的稳定 ID 对照表。
重新排列图集时，已有格子通过这个对照表找到原来的资源；翻转信息也会保留。
**不要删除该属性。调整图块编号后，先在 Yapshire 中加载并保存相关地图，再继续用 Tiled 编辑**，
以便更新编号和对照表。没有对照表的新 Tiled 地图按当前图集解释。
删除或重命名仍被引用的 ID 会明确报错；不要把旧 ID 静默挪作其他用途。

图块固定 16×16，图集没有间距和边距，PNG 尺寸是 16 的倍数，单边最多 4096 像素。
动画沿用 Tiled 的 `animation`，要求连续帧及一致的正数帧时长。官方水体包含 27 组四帧动画。

## 方块、模型与不规则轮廓

方块定义保存身份和规则，模型定义可见部件，地图保存放置实例。官方两张场景中的地形、水体、
建筑、家具、路灯、栅栏和植物现已接入这套定义。树木和建筑由独立 PNG 部件组成；天空、远山、云仍保留为背景。
旧街景 PNG 为兼容旧布局而保留，默认小镇已不再用它显示整张前景。
旧物件碎片只保留在兼容图集中，不再为它们重复导出方块、模型和单片 PNG。

例如，在清单的 `blocks` 与 `models` 中分别登记 `my_pack:oak`。物件 JSON：

```json
{
  "model": "my_pack:oak",
  "colliders": [{"rect": [-3, -24, 6, 24]}],
  "selection": [[-20, -56, 16, 24], [4, -56, 16, 24], [-3, -32, 6, 32]]
}
```

对应模型 JSON：

```json
{
  "size": [40, 56],
  "anchor": [20, 56],
  "parts": [
    {"texture": "textures/oak/trunk.png", "offset": [17, 24], "size": [6, 32]},
    {"texture": "textures/oak/leaves.png", "offset": [0, 0], "size": [16, 24]},
    {"texture": "textures/oak/leaves.png", "offset": [24, 0], "size": [16, 24], "flip_x": true}
  ]
}
```

部件偏移相对模型左上角；碰撞、选中矩形与交互矩形相对放置锚点，均以像素计，x 向右、y 向下。
部件按列表顺序叠放，使用最近邻缩放并保留 PNG 透明度。树枝可以跨格伸出、留下透明分叉，
只为树干配置碰撞，不必填满正方形。部件贴图可以被其他模型复用，也能登记为更小的物件单独放置。

`selection` 可省略：默认按各部件的矩形选中，**不逐像素检测透明度**。
需要让鼠标穿过枝条空隙时，可显式配置多个选中矩形。`colliders` 默认为空；
碰撞矩形设 `platform: true` 即为单向平台。碰撞范围不依赖贴图轮廓或选中范围。

物件可选字段包括 `behavior`（`decoration`、`portal`、`shop`、`fishing`、`toggle`）、
`interaction: [x,y,w,h]`、默认字符串 `properties` 和 `states`。
每种状态指定 `model` ID，可额外替换 `colliders`；初始状态为 `default`。
`toggle` 必须提供 `open` 状态，按 E 在默认与打开之间切换。官方木桶演示的是联机同步的桶盖，尚无储物背包。
传送门定义可设置 `target_map` / `target_spawn`，实例属性可覆盖它们；移动门时入口区域一起移动。

在 Tiled 中放置 **point**，Type 填 `block`，字符串属性 `block` 填 `my_pack:oak`，
可选字符串属性 `state` 默认为 `default`。点坐标就是模型锚点。
Yapshire 显示完整模型，Tiled 显示点标记。模型定义及部件美术通过 JSON/PNG 编辑，游戏内编辑器用于摆放实例。

地形定义设 `tile: true`，要求静态 16×16 模型、锚点 `[0,0]`、装饰行为且没有状态变体。
`.tsj` 中每格的字符串属性 `block` 指向它。在源码仓库中修改贴图或登记新地形后，执行：

```sh
uv run --with Pillow tools/compile_pack.py assets/packs/my_pack
cargo run -p yapshire-server -- --maps assets/packs/my_pack --check
```

编译工具从源模型重建图集，保留已有图块编号与动画，把新地形加入 `generated/blocks.tsj`，不改地图布局。
重启游戏加载新资源。组合物件直接读取部件 PNG，修改 JSON/PNG 后重启即可。
不要用 `tools/draw_maps.py` 处理社区作品，它会重建官方默认资源和地图。

## 坐标、遮挡和碰撞

Tiled 左上角为原点，x 向右、y 向下。角色位置指脚底，换算关系为：
`world_x = tiled_x`，`world_y = 地图行数 × 16 - 64 - tiled_y`。
默认 17 行地图中，Tiled 的 `y=208` 就是原来的地面。地图尺寸和图层数可以改变。

| 定义 | 效果 |
| --- | --- |
| 图块字符串属性 `collision` | `none` 无碰撞、`solid` 实心、`platform` 单向平台 |
| 图块字符串属性 `block` | 使用定义里的局部碰撞矩形，优先于旧的碰撞字符串 |
| `block` 点对象 | 使用模型、实例状态和相对锚点的碰撞区域 |
| tile layer 布尔属性 `collision` | 设为 `true` 后，该层使用图块的碰撞定义 |
| `solid` 矩形对象 | 独立于美术的实心碰撞区域 |
| 图层数值属性 `z` | 叠放顺序，默认 `-30 + 图层序号 × 6` |
| 图层 `visible` / `opacity` | 控制显示；隐藏美术不会删除物理碰撞 |

角色能站在不同高度的地面上，从下方穿过单向平台，在下落时落到平台上，并受到墙面和天花板阻挡。
掉出地图底部后回到该地图的出生点。镜头范围随地图尺寸变化。
角色叠放顺序为 `z=5`；前景物件放在更高的图层，背景家具放在更低的图层。
美术外轮廓与实际占地不一致时，另画 `solid` 矩形。预设碰撞矩形不支持斜坡和旋转。

背景 image layer 使用清单登记的 PNG 和像素偏移。
天空、云等室外氛围仍是游戏共用表现，作者可用背景层覆盖。
暂不支持嵌套图层、无限分块、压缩数据、带 `gid` 的 tile object、Tiled 模板、多边形和视差层；会明确拒绝这些格式。

## 纯 2D 像素渲染

世界采用正交镜头，所有图层都保持一个世界单位对应一个画布像素，`z` 只决定遮挡顺序。
原尺寸部件、地形与人物共用同一套像素网格，不使用透视投影、水平 XZ 地面或按距离缩小物件。

镜头边缘始终对齐整数世界像素，包括画布宽高为奇数的情况。
2x/3x/4x 设置改变画布分辨率，再用最近邻采样放大；图块翻转、动画和模型透明镂空仍然可用。
新部件请使用整数坐标与 PNG 原始尺寸。树皮、分叉枝条、叶簇、墙板、屋瓦和门窗分别制作，
复用完整的结构部件，不把画好的整棵树或整栋房屋按格子硬切。

## 像素材质模拟

方块可添加 `"material": "solid"`、`"sand"` 或 `"water"`。同时在 tile 或 object 图层添加 Tiled 属性：

```json
{"name": "simulation", "type": "bool", "value": true}
```

两项必须同时存在：没有启用模拟的图层仍使用原来的图片与预设碰撞。
材质方块使用 `decoration` 行为，不可带状态。默认地图的 Terrain 和 Water 层已启用。
编辑器提供 `yapshire:materials/sand` 和 `yapshire:materials/water` 印章；放置材质模型时，
会在同一次可撤销编辑中启用物件层的模拟。

创建房间时，按模型部件的尺寸、偏移、锚点和翻转读取 PNG 颜色与透明轮廓。
透明度低于 128 的位置为空，其余生成材质像素；使用原始尺寸即可一对一保留贴图像素。
高层的非空像素覆盖低层，所有材质层合并为一个物理平面，绘制在 `z=-1`。
隐藏的材质仍参与物理，模拟图层必须完全不透明。背景装饰和前景应留在普通图层。
材质碰撞来自实心像素；其他方块、门、商店和平台继续使用原有交互与碰撞。

在房间中按 **V** 打开工具，**1/2/3** 选择挖掘、沙子或水，按住鼠标左键使用。
笔刷半径为 5 像素，作用距离为角色周围 48 像素；输入聊天、菜单和钓鱼面板会阻止笔刷操作。
沙子下落堆积，水流向空处，沙子可沉入水中。固体和沙子阻挡角色，挖洞同时改变碰撞。
原有静态碰撞会挡住水沙，不能用此工具挖除。

只有房间的 Rust 服务端以 20 Hz 推进模拟，通过游程编码发送变化的 32×32 区块，
加入快照包含已修改区块。局域网与 Cloudflare 网关共用协议 **5**。
Tilemap 与组合模型继续作为可编辑模板，不为每个材质像素创建实体或精灵。

限制：每个房间所有模拟地图的矩形面积合计不超过 **524288 像素**；解码后的材质贴图也有相同总量限制，
模板栅格化工作量最多为该数值的四倍。现场变化保留到房间销毁或服务端重启。
编辑器保存的是初始模板，不是当前沙水状态。尚未实现燃烧、刚体坍塌、游泳与化学反应。
角色移动仍沿用客户端上报的位置，材质由服务端计算并不等于移动防作弊。

## 出生点、门、商店和钓鱼区域

在 `objectgroup` 中设置对象的 **Type**（也兼容旧版导出的 `class`），旋转为零，数字对象 ID 为正数且唯一。
每张地图至少有一个具名出生点。

| Type | 形状 | 属性及行为 |
| --- | --- | --- |
| `spawn` | 点 | 唯一 `name`，供入口和传送门引用 |
| `block` | 点 | 字符串 `block` ID、可选 `state`；外观与行为来自定义 |
| `portal` | 矩形 | 字符串 `target_map`、`target_spawn`；区域内按 E 传送 |
| `shop` | 矩形 | 按 E 打开现有渔具店；店员位置随区域移动 |
| `fishing` | 矩形 | 按 E 开始现有钓鱼小游戏，向右抛竿 |
| `solid` | 矩形 | 实心碰撞，不自动提供美术 |
| `prefab` | 点 | 字符串 `prefab` 指向清单内的物件 ID |

物件包含以格子计的 `width` / `height`、以像素计的 `anchor: [x,y]`，以及按行排列的稳定 ID 数组 `tiles`。
空字符串代表透明格。对象位置减去锚点后必须对齐 16px 网格，完整物件必须位于地图范围内。
这类点对象在 Yapshire 中渲染为完整物件，在 Tiled 中显示为标记；若必须在 Tiled 中看到美术，
使用旧式图块印章。旧 prefab 的碰撞另用 `solid` 矩形定义。
新增物件推荐使用 `block`，让美术与规则随实例一起放置。
交互区域复用现有渔具商店与钓鱼规则，本版不包含自定义商品经济和鱼种表。

增加新地点：复制一张 `.tmj`，在 `pack.json.maps` 中登记新的稳定 ID，放置 `arrival` 出生点，
把门的 `target_map` / `target_spawn` 指向它，再按相同方法设置回程门。
新地图、移动门店入口或移动垂钓区都不需要修改 Rust；使用新图片时先登记相关资源。

## 自动连接地形

官方地面图集包含完整的 **Quay** 十六种边连接变体，可直接用 Tiled 的 Terrain Brush 绘制。
游戏内画笔、填充和擦除也会重新计算该层的相邻地形。

`terrains["my_pack:stone"]` 按掩码 `0..15` 登记稳定 ID，位为：**北 1、东 2、南 4、西 8**。
对应方向连接同种地形时置位。每块地形图块带同名字符串 `terrain` 属性。
全部变体必须位于同一图集；补充对应 `wangsets` 后即可用 Tiled 的地形笔刷。
本版处理单种材质的四边连接，不自动混合两种材质，也不处理角连接地形。

## 联机、旧地图迁移和边界

服务端在开放端口前校验内容包，加入时发送定义、地图布局及世界版本。
客户端比较包 ID、版本、JSON 定义和图片 SHA-256，完全一致后才发送 `world_ready`。
不匹配时显示缺失或不同的资源；PNG 与脚本不会从服务端自动下载。
远程布局仅保存在内存，离开房间恢复本地地图。移动消息携带地图稳定 ID，身处不同地点的玩家互相隐藏；
服务端拒绝未知地图，并按地图边界限制坐标。

物件交互发送地图 ID 与对象 ID，Rust 服务端检查其登记行为及玩家最近上报的位置是否位于交互区域，
再广播状态变化。后来加入的玩家收到当前状态快照，不同房间彼此独立。
状态只保存在房间内存，服务端重启后重置，也不会写入本地编辑器文件。
局域网与 Cloudflare 网关使用相同服务端逻辑。新增可执行行为仍需写 Rust，内容包不能加载任意代码。

原来引用 `harbor.tsj` 的 `town.tmj` / `tackle-shop.tmj` 可以从旧编辑器或服务端目录导入。
若旧目录包含图集和 PNG，必须与原版一致。迁移表覆盖原来的 359 个图块，保留翻转及美术布局，
并补入原有地面碰撞和交互对象。加载不会修改文件；明确点击保存后才写入新目录结构，
保留原字节的 `.tmj.bak`，旧文件仍留在原处。

边界：每包最多 32 张地图、32 个图集、8192 个图块；每图最多 32 层，2–256 列、4–128 行，
每对象层最多 256 个对象；单图 1 MiB，世界消息 8 MiB，单资源文件 4 MiB，加载资源总量 32 MiB。
方块和模型定义各最多 8192 个；每模型最多 128 个部件，单边最多 1024px；每物件最多 64 个碰撞矩形、
128 个选中矩形和 16 种状态。定义文件及引用贴图均参与内容一致性校验。

格式依据 Tiled 的 [JSON 文件规范](https://doc.mapeditor.org/en/stable/reference/json-map-format/)、
[GID 规则](https://doc.mapeditor.org/en/stable/reference/global-tile-ids/)
和[地形规则](https://doc.mapeditor.org/en/stable/manual/terrain/)。
